# Передача работы: что сделано и что дальше

Записка следующей сессии. Ветка `claude/delivery-simulator-prototype-qy5zst`,
последний коммит — БИЛЕТОН 1.8.0, 246 тестов зелёные, рабочее дерево чистое.

## Что это за проект

Монорепозиторий из трёх учебных экономических симуляторов на ванильном JS
(ES-модули, без зависимостей). Общее ядро в `shared/`, у каждой игры свой
`src/model` (чистые функции, `step(state, input) -> {state, report}`) и
`src/ui/app.js`. Сборка — `node shared/tools/build.js [игра]`, на выходе один
самодостаточный HTML в `games/*/dist/`.

| игра | ход | партия | версия |
|---|---|---|---|
| НОВОЕДА (foodtech) — доставка еды | неделя | 52 | 1.6.0 |
| КИНОПОТОК (cinema) — онлайн-кинотеатр | месяц | 36 | 1.5.0 |
| БИЛЕТОН (tickets) — билетный сервис | месяц | 36 | 1.8.0 |

Версии независимы, лежат в `games/*/build.manifest.js` и подставляются в имя
файла. Тест `shared/tests/compat.test.mjs` следит, чтобы ссылки на имя файла
в README, витрине и всех доках не протухли.

## Метод, которым тут проверяется баланс

Не «мне кажется», а замер. Для каждой игры есть скрипт одномерных срезов:
держим осмысленную опорную стратегию и двигаем один рычаг по всему диапазону
на 4–6 сидах за полную партию. **Если лучший ответ лежит на упоре ползунка —
рычага нет, есть кнопка «сделать хорошо».** Так были найдены и исправлены:
цена доставки и комиссия в НОВОЕДЕ, пробный период в КИНОПОТОКЕ, цели совета
директоров в обеих играх.

Скрипты лежат в скретчпаде сессии (он не переживает сессию) — их придётся
написать заново, это полчаса. Шаблон виден по описаниям в коммитах.

## Незакрытое, по убыванию ценности

### 1. Абонплата и ставка платформы в БИЛЕТОНЕ мертвы

Оба рычага монотонно вниз: правильный ответ всегда «не брать ничего».

```
ставка платформы:  0% -> 7.57 млрд у основателя,  7% -> 5.95 млрд
абонплата:         0 ₽ -> 7.55 млрд,            120к -> 4.86 млрд
                                        (организаторов 684 -> 279)
```

**Проверенная и отвергнутая гипотеза.** Я поднял ценность виджета для
организатора (`platformFit` в `games/tickets/src/model/supply.js`,
коэффициент 0.95 -> 1.7). Общий уровень вырос (6.81 -> 9.13 млрд), а форма
кривой не изменилась вообще: 0% по-прежнему лучше 7%. Правку откатил.
**Не повторяйте её.**

Причина глубже: `subscriptionDrag` и `feltTake` в `supply.js` бьют по притоку
организаторов сильнее, чем любые деньги, которые с них удаётся собрать при
нынешнем размере базы на виджете. Чинить надо связку, а не коэффициент:
абонплата должна что-то давать взамен — приоритет в афише, лимиты, уровень
поддержки, — а не быть чистым вычетом из привлекательности.

После правки обязательно перепроверить остальные девять рычагов и проходимость
целей совета: они калибровались по распределению (год 1 берут 32% стратегий,
год 2 — 13%, год 3 — 17%).

### 2. Панель «Что в городе» — только в БИЛЕТОНЕ

Сделана в `games/tickets/src/ui/app.js` (`buildNews` / `renderNews`), слот
`#news-slot` в `index.html`. Каждая строка выведена из состояния модели.

В двух других играх материал уже есть и не показывается словами: в НОВОЕДЕ
погода с прогнозом на неделю вперёд (`weatherNext`), в КИНОПОТОКЕ премьеры,
ходы конкурента и истечение прав. Самый дешёвый перенос готового решения.

### 3. Счётчик оборота по типам организаторов (БИЛЕТОН)

Возврат аванса (`advanceRecoupRate`) считается от доли типа в выставленных
местах, потому что отдельного счётчика оборота по типам нет. Для аванса
точности хватает, для чего-то большего — нет.

## Чем проверять после любой правки

```
npm test                          # 246 тестов
node shared/tools/build.js        # пересборка всех трёх
```

Плюс браузерные прогоны через Playwright (`/opt/node22/lib/node_modules/playwright`),
их тоже придётся написать заново. Что они проверяли:

* три игры × два языка × модуль и собранный файл × 14 ходов: нет ошибок
  в консоли, KPI на месте, нет горизонтального переполнения;
* телефон 390×844: итоги хода выше рычагов, полоса кнопок внизу экрана;
* все таблицы влезают в свою панель на 390 и 1440 и у каждой ячейки есть
  подпись (на телефоне таблицы показываются карточками, подписи ставит
  `shared/tables.js` через MutationObserver);
* каждое синее слово — ссылка, и каждая ссылка куда-то ведёт.

Последнее правило стоит помнить: **синий цвет в этих играх означает
«кликабельно» и больше ничего.**

## Чего делать не надо

* Не ставить API новее Safari 14.1 — есть денежный список в `compat.test.mjs`.
  Игру открывают одним файлом на чужом ноутбуке.
* Не звать `labelTables()` руками из панелей: наблюдатель уже висит.
* Не трогать `docs/*/economics.md` в отрыве от модели: там записаны
  измеренные числа, и они должны сходиться с кодом.
* GitHub Pages до сих пор не включён — это делается только вручную в
  Settings → Pages → Source: GitHub Actions. Все прогоны воркфлоу падают
  на `configure-pages`, тесты и сборка при этом проходят.
