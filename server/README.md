# Сервер мировой таблицы результатов

Игры умеют показывать глобальную таблицу и отправлять в неё результаты, но
сервер для этого нужно развернуть один раз вручную — бесплатно, на Google
Apps Script поверх обычной Google Таблицы. Занимает 5 минут.

Сервер **универсальный**: списка игр в коде нет. Игра — это тег в строке
результата («НОВОЕДА», «КИНОРЕКА·сложный», «НОВОГРАД+»…), и любой тег,
прошедший проверку формата, заводит свою таблицу сам. Новые игры, уровни
сложности и акты НЕ требуют правок сервера — достаточно, чтобы игра
печатала свой тег в строке результата (`shared/records.js`).

## Развёртывание (один раз)

1. Создайте новую [Google Таблицу](https://sheets.new) (например,
   «Симуляторы — рекорды»). Записи будут копиться на листе `scores`.
2. В меню таблицы: **Расширения → Apps Script**. Удалите заглушку и вставьте
   целиком содержимое файла `server/leaderboard.gs`. Сохраните.

   > Открывать редактор надо **из таблицы**: тогда проект привязан к ней и
   > находит её сам. Проект, созданный отдельно на `script.google.com`
   > (в заголовке «Проект без названия»), никакой таблицы не знает —
   > для него смотрите «Отдельный проект» ниже.
   Рекомендуется сразу сузить доступ скрипта до одной таблицы: в настройках
   проекта (шестерёнка) включите «Показывать файл манифеста appsscript.json»
   и замените его содержимое на `server/appsscript.json` — scope
   `spreadsheets.currentonly` даёт скрипту доступ только к той таблице,
   из которой он создан, а не ко всем таблицам аккаунта.
3. **Развернуть → Новое развёртывание → Тип: Веб-приложение**:
   * «Выполнять от имени» — **от моего имени**;
   * «У кого есть доступ» — **у всех**.
   Нажмите «Развернуть» и скопируйте URL вида
   `https://script.google.com/macros/s/…/exec`.
4. Проверьте развёртку: откройте в браузере `…/exec?ping=1` — должно
   ответить `{"ok":true,"api":2,"mode":"bound","rows":0}`.
5. Впишите URL в файлы `games/*/index.html` (всех четырёх игр) — в блоке
   `only-modular` есть строка:

   ```js
   window.__lbEndpoint = null;
   ```

   Замените `null` на `'https://script.google.com/macros/s/…/exec'`
   и запушьте: сайт пересоберётся сам.

Офлайн-файлы (`dist/*.html`) адреса сервера не содержат: в классе без
интернета таблица просто не показывается, и игра ничего никуда не шлёт.

## Обновление скрипта (когда в репозитории поменялся leaderboard.gs)

1. Откройте таблицу → **Расширения → Apps Script**.
2. Замените содержимое файла целиком свежим `server/leaderboard.gs`.
3. **Развернуть → Управление развёртываниями → карандаш → Версия: Новая
   версия → Развернуть.** URL при этом НЕ меняется, клиенты ничего не
   замечают.
4. Проверьте `…/exec?ping=1` — ответ вида
   `{"ok":true,"api":2,"mode":"bound","rows":42}` означает: сервер новой
   версии, таблицу видит, записей в ней 42. При `ok:false` читайте поле
   `error`. Если вместо JSON открывается страница входа Google, дело не в
   коде: у развёртывания «У кого есть доступ» должно стоять **«Все»**,
   «Выполнять от имени» — **«от моего имени»**.

Накопленные записи живут в таблице, а не в скрипте: обновление кода их
не трогает. Протокол обратно совместим — старые страницы игр продолжают
работать с новым сервером и наоборот.

## Что проверяет сервер

* **Контрольную сумму** строки результата (тот же djb2-xor, что печатает
  игра); счёт, код партии и ходы разбираются из строки — присланные
  отдельно числа сервер не читает. Потолки: счёт до 10^15, ходов до 500,
  строка до 200 символов.
* **Формат тега игры**: буквы (латиница/кириллица), цифры, «+», «·уровень»,
  до 40 символов. Никакого списка игр — см. «Закрытый список» ниже, если
  он вдруг понадобится.
* **Имя** — до 24 символов, чистится от управляющих символов; та же строка
  от того же имени второй раз не записывается (повторное нажатие просто
  возвращает место).

## API

| Запрос | Ответ |
|---|---|
| `GET ?ping=1` | `{ok, api, mode, rows}` — жив ли сервер и видит ли таблицу |
| `GET ?games=1` | `{ok, games:[…]}` — теги, уже приславшие результаты |
| `GET ?game=ТЕГ&limit=10` | `{ok, top:[{name, score, seed, turns, version, date}], total}` |
| `GET ?game=ТЕГ&seed=КОД` | тот же топ, но только партии этого кода |
| `POST {game, name, line}` | `{ok, rank, total}` либо `{ok:false, error}` |

Ответы `GET` кэшируются на минуту: класс, разом открывший финальные
экраны, читает из кэша. Отправка результата сбрасывает кэш своей игры.

## Отдельный проект (если скрипт не привязан к таблице)

Со смартфона легко создать не привязанный к таблице проект: меню
«Расширения» есть только в браузерной версии таблицы, а `script.google.com`
открывается всегда. Такой проект тоже работает, но ему надо сказать, с какой
таблицей он живёт, и дать более широкое разрешение:

1. Apps Script → шестерёнка **«Настройки проекта»** → **Свойства скрипта** →
   добавьте свойство `SHEET_ID`. Значение — идентификатор таблицы из её
   адреса (`docs.google.com/spreadsheets/d/ЭТА_ЧАСТЬ/edit`); можно вставить
   и ссылку целиком, сервер вырежет идентификатор сам.
2. В `appsscript.json` замените строку разрешения на общую — отдельный
   проект не может пользоваться `spreadsheets.currentonly`:

   ```json
   "oauthScopes": ["https://www.googleapis.com/auth/spreadsheets"]
   ```

3. Выпустите новую версию и один раз выполните в редакторе любую функцию,
   чтобы выдать разрешение.

Проверка: `…/exec?ping=1` ответит `{"ok":true,"api":2,"mode":"byId","rows":N}`.
У привязанного проекта в поле `mode` будет `bound`. Если `ok:false` — в поле
`error` написано, чего именно не хватает.

## Закрытый список игр (опционально)

По умолчанию сервер принимает любой корректный тег. Если захочется жёстко
ограничить приём (например, от самодельных тегов на открытом уроке):
Apps Script → шестерёнка «Настройки проекта» → **Свойства скрипта** →
добавьте свойство `GAMES` со значением через запятую:

```
НОВОЕДА, НОВОЕДА·лёгкий, НОВОЕДА·сложный, КИНОРЕКА, БИЛЕТВИЛЬ, НОВОГРАД, НОВОГРАД+
```

Удаление свойства возвращает свободный приём. Переразвёртка не нужна:
свойства читаются на каждом запросе.

## Тесты

Логика сервера накрыта тестами в репозитории:
`shared/tests/leaderboard-server.test.mjs` исполняет `leaderboard.gs` в
песочнице node с заглушками служб Apps Script и проверяет протокол теми же
строками результата, что печатают игры (13 сценариев: подделка счёта,
дубли, новые теги, фильтр по коду, кэш, битый ввод). Они гоняются обычным
`npm test` — регрессия протокола ловится до ручного деплоя.

## Модерация

Все записи лежат в обычной таблице — строку с неприличным именем можно
просто удалить, таблица этого не заметит. Резервная копия — «Файл →
Скачать». Кэш переживёт удаление максимум минуту.
