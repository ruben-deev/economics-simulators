# НОВОЕДА — экономический симулятор доставки еды

Учебная браузерная игра: вы управляете сервисом доставки еды (аналог Яндекс Еды) в вымышленном
городе Новоград. Каждый ход — одна неделя. Вы двигаете рычаги бизнеса и смотрите, как они
проходят через модель спроса, предложения и денег.

Игра сделана в первую очередь как **учебный тренажёр**: важнее не выиграть, а увидеть,
почему решения ведут именно к таким последствиям. Поэтому в интерфейсе есть разбор каждой
недели по факторам, таблица юнит-экономики, отчёт P&L и объяснение формул.

## Быстрый старт

Вариант 1 — один файл, без установки:

```
node tools/build.js
```

и открыть `dist/game.html` двойным кликом. Файл самодостаточный: работает офлайн,
без сети и без сборщиков. (Собранный файл уже лежит в репозитории.)

Вариант 2 — с локальным сервером (нужен для разработки, т.к. ES-модули не грузятся по `file://`):

```
npm start          # http://localhost:8080
```

Тесты модели:

```
npm test
```

## Чем управляет игрок

| Рычаг | Что делает | Обратная сторона |
|---|---|---|
| Стоимость доставки | прямая выручка с заказа | спрос эластичен, в студенческом районе особенно |
| Комиссия с ресторана | основная выручка | высокая комиссия отпугивает рестораны → падает ассортимент |
| Оплата курьеру за заказ | главная переменная себестоимость | ниже рынка — никто не выходит на смену |
| Целевой штат курьеров | пропускная способность | нанять можно только столько, сколько придёт откликов |
| Маркетинг | узнаваемость → новые клиенты | убывающая отдача, узнаваемость «забывается» |
| Промо-скидка | мгновенный рост спроса | прямой вычет из вклада с заказа |
| Подключение ресторанов | ассортимент | стоит денег каждую неделю |
| Технологии | производительность курьера, скорость, поддержка | накопительная инвестиция, окупается не сразу |
| Покрытие города | 6 районов с разной экономикой | разовая стоимость запуска + постоянное содержание |
| Раунды инвестиций | деньги на рост | размытие вашей доли |

## Что моделируется

* **Спрос** — база клиентов (запас) × частота заказов (поток). Частота зависит от цены,
  скорости доставки, ассортимента и сезона.
* **Предложение** — пропускная способность курьеров. При загрузке выше 90% время доставки
  растёт лавинообразно (кубическая зависимость от загрузки).
* **Рынок труда** — курьеры приходят, только если заработок обгоняет рыночный; уходят,
  если недоплачивают или перегружают.
* **Рестораны** — подключаются за счёт отдела продаж, уходят при высокой комиссии
  и низком потоке заказов.
* **Деньги** — недельный P&L с разделением на переменные и постоянные расходы, касса,
  банкротство при нуле на счету.
* **События** — 13 случайных событий, часть из них требует решения игрока.
* **Оценка компании** — годовая выручка × мультипликатор от роста и рентабельности.
  Итоговый счёт = оценка × ваша доля.

Подробный разбор всех формул и допущений — в [docs/economics.md](docs/economics.md).
Сценарии занятий и вопросы для разбора — в [docs/teacher-guide.md](docs/teacher-guide.md).

## Структура проекта

```
index.html              разметка игры
src/styles.css          оформление
src/model/config.js     ВСЕ параметры мира: районы, константы, рычаги
src/model/engine.js     ядро симуляции — чистые функции, без DOM
src/model/events.js     случайные события
src/model/rng.js        детерминированный ГПСЧ (партия воспроизводима по seed)
src/ui/                 интерфейс: рычаги, графики, отчёты
tests/engine.test.mjs   тесты модели (24 проверки)
tools/build.js          сборка dist/game.html одним файлом
tools/serve.js          локальный статический сервер
```

Вся экономика сосредоточена в `src/model`. Модуль не знает про браузер, поэтому его можно
гонять в тестах, в скриптах и строить по нему графики чувствительности.

## Настройка баланса под свой курс

Все числа вынесены в `src/model/config.js`: стартовый капитал, стоимость запуска районов,
рыночная зарплата курьера, эластичности, отток клиентов и т. д. Менять их можно, не трогая
логику. После правки полезно прогнать `npm test` — тесты проверяют не конкретные числа,
а качественные свойства модели (монотонность реакций, сходимость P&L, отсутствие NaN).

## Ограничения модели

Это учебная модель, а не прогнозный инструмент. Конкурент не реагирует на ваши действия,
рестораны не торгуются индивидуально, клиенты внутри района однородны, а вся логистика
свёрнута в один показатель «заказов на курьера». Модель показывает **структуру**
зависимостей фудтех-бизнеса, а не предсказывает конкретный рынок.
