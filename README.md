# Учебные экономические симуляторы

*[English version](README.en.md)* · автор — **[Ruben Deev](https://www.linkedin.com/in/ruben-deev)**

**▶ [Открыть витрину со списком игр](https://ruben-deev.github.io/economics-simulators/)**

Две браузерные игры про управление бизнесом. Каждая — один ход в единицу времени, десяток
рычагов и понятная причина, по которой можно разориться. Сделаны в первую очередь как
**учебные тренажёры**: важнее не выиграть, а увидеть, почему решения ведут именно к таким
последствиям. Поэтому в интерфейсе есть разбор каждого хода по факторам, таблица
юнит-экономики, отчёт P&L и объяснение формул.

Интерфейс двуязычный — кнопка **RU / EN** в шапке. Выбор запоминается между сессиями
и общий для всех трёх игр.

| Игра | Бизнес | Ход | Партия | Главный конфликт |
|---|---|---|---|---|
| [🛵 **НОВОЕДА**](https://ruben-deev.github.io/economics-simulators/games/foodtech/) | доставка еды | неделя | 52 недели | спрос против пропускной способности |
| [🎬 **КИНОПОТОК**](https://ruben-deev.github.io/economics-simulators/games/cinema/) | онлайн-кинотеатр | месяц | 36 месяцев | война за рынок с живым конкурентом |
| [🎟️ **БИЛЕТОН**](https://ruben-deev.github.io/economics-simulators/games/tickets/) | билетный сервис | месяц | 36 месяцев | двусторонний рынок и конфликт каналов |

Игры устроены одинаково, но намеренно моделируют **разные** типы экономики:
в доставке выручка с клиента растёт вместе с его активностью, в подписке она
фиксирована, а расход растёт, в билетном сервисе через вас проходят миллиарды,
а вашими становятся проценты. Одни и те же слова — «вовлечённость», «удержание»,
«рост» — означают в них разные вещи. Это лучше всего видно, если сыграть
в несколько.

> Если ссылки не открываются, значит в репозитории ещё не включены GitHub Pages:
> Settings → Pages → Source: **GitHub Actions**. После этого достаточно перезапустить
> workflow «Deploy games to GitHub Pages» — дальше он публикует игры при каждом пуше.

## Быстрый старт

Проще всего — [открыть в браузере](https://ruben-deev.github.io/economics-simulators/).
Ставить ничего не нужно.

Для раздачи студентам офлайн скачайте одиночный файл:
[доставка](https://ruben-deev.github.io/economics-simulators/games/foodtech/dist/novoeda-delivery-simulator-v1.9.2.html) ·
[кинотеатр](https://ruben-deev.github.io/economics-simulators/games/cinema/dist/kinopotok-streaming-simulator-v1.10.1.html).
Это самодостаточные HTML: открываются двойным кликом и работают без сети.

Локально:

```
npm start          # http://localhost:8080 — витрина со списком игр
npm test           # тесты моделей и переводов всех трёх игр
npm run build      # пересобрать одиночные файлы игр в games/*/dist/
```

Собранные файлы уже лежат в репозитории, поэтому шаг сборки нужен только после правок.

**Новая версия.** У каждой игры своя версия — поле `version` в её `build.manifest.js`.
Они независимы: правка в кинотеатре не переименовывает файл доставки и не делает
вид, что он тоже обновился. `package.json` остаётся версией монорепозитория целиком.
Номер игры попадает в имя собранного файла (`…-simulator-v1.1.0.html`), внутрь самой
страницы и в справку по кнопке «?». Сборка версии заодно удаляет из `dist/` предыдущую, чтобы не гадать,
какой файл раздавать. Ссылки в README, на витрине и в методичках содержат версию;
если забыть их обновить, тест `shared/tests/compat.test.mjs` перечислит все устаревшие.

**Файл или ссылка.** Одиночный файл рассчитан на ноутбук: там его открывают
двойным щелчком, и он работает без сети. На телефоне надёжнее ссылка. Причина —
просмотрщик документов: и «Быстрый просмотр» на маке, и просмотр пересланного файла
в Телеграме или другом мессенджере показывают HTML, но **намеренно не выполняют
JavaScript**. Встроенный браузер того же Телеграма скрипты выполняет — разница
именно между «переслали файл» и «дали ссылку».
Игра — расчётная модель, без скриптов от неё остаётся пустой каркас. Теперь в
этом случае страница сама объясняет, что произошло и как открыть её в браузере.

**Важно:** `games/<игра>/index.html` из папки двойным щелчком не откроется — браузер
не грузит ES-модули с `file://`, и в Safari, и в Chrome. Для запуска с диска
используйте файл из `dist/`, для разработки — `npm start`. Если открыть модульную
версию из папки, страница сама объяснит, что делать.

**Совместимость.** Планка — браузеры весны 2021 года (Safari 14.1, Chrome 90).
Список более новых API, которые в код попадать не должны, лежит в
`shared/tests/compat.test.mjs` и проверяется на собранных файлах: одна такая
функция превращает игру в пустую страницу на чужой машине, без единой подсказки.

# 🛵 НОВОЕДА — доставка еды

Вы управляете сервисом доставки еды в вымышленном городе Новоград. Каждый ход — неделя.

Курьеров не хватает — время доставки растёт лавинообразно, клиенты уходят. Курьеров
много — платите за простой. Это главная петля игры, и она не решается одним числом.

### Чем управляет игрок

| Рычаг | Что делает | Обратная сторона |
|---|---|---|
| Стоимость доставки | прямая выручка с заказа | спрос эластичен, в студенческом районе особенно |
| Комиссия с ресторана | основная выручка | высокая комиссия отпугивает рестораны → падает ассортимент |
| Оплата курьеру за заказ | главная переменная себестоимость | ниже рынка — никто не выходит на смену |
| Целевой штат курьеров | пропускная способность | нанять можно только столько, сколько придёт откликов |
| Маркетинг | узнаваемость → новые клиенты | убывающая отдача, узнаваемость «забывается» |
| Промо-скидка | мгновенный рост спроса | прямой вычет из вклада с заказа |
| Надбавка за плохую погоду | удерживает курьеров на линии в шторм | условный расход: в ясную погоду не стоит ничего |
| Подключение ресторанов | ассортимент | стоит денег каждую неделю |
| Технологии | производительность курьера, скорость, поддержка | накопительная инвестиция, окупается не сразу |
| Data Science | качество алгоритмов | без данных бесполезен, а данные копятся только от заказов |
| Покрытие города | 6 районов с разной экономикой | разовая стоимость запуска + постоянное содержание |
| Раунды инвестиций | деньги на рост | размытие вашей доли |

### Что моделируется

* **Спрос** — база клиентов (запас) × частота заказов (поток), зависящая от цены,
  скорости доставки, ассортимента и сезона.
* **Предложение** — пропускная способность курьеров. При загрузке выше 90% время
  доставки растёт лавинообразно (кубическая зависимость).
* **Рынок труда** — курьеры приходят, только если заработок обгоняет рыночный.
* **Рестораны** — подключаются за счёт отдела продаж, уходят при высокой комиссии.
* **Погода** — постоянный фактор недели с сезонным распределением. Бьёт с двух сторон
  сразу: поднимает спрос и режет пропускную способность.

| Погода | Спрос | Мощность курьеров | Отток курьеров |
|---|---|---|---|
| Ясно | — | — | — |
| Дождь | +16% | −8% | +4 п.п. |
| Мороз | +14% | −12% | +7 п.п. |
| Снегопад | +22% | −18% | +9 п.п. |
| Жара | +4% | −14% | +10 п.п. |
| Гололёд | +10% | −26% | +16 п.п. |
| Шторм | +30% | −20% | +12 п.п. |

Прогноз на следующую неделю публичен. Ценность не в информации, а в реакции: курьеры,
нанятые сегодня, выходят на линию именно на той неделе, к которой относится прогноз.

### Алгоритмы

| Алгоритм | Что делает | Чем платите |
|---|---|---|
| Объединение заказов (батчинг) | курьер везёт несколько заказов за поездку | каждый заказ едет дольше |
| Прогноз спроса и автонайм | штат подбирается под прогноз и целевую загрузку | ошибка прогноза, потеря ручного контроля |
| Персональные скидки | скидка уходит только тем, кто без неё не закажет | промахи модели и ощущение несправедливости |
| Динамическое ценообразование | надбавка в часы пик, сглаживание пиковой нагрузки | клиенты не любят непредсказуемую цену |
| Умное распределение курьеров | приоритет районам с высоким вкладом | сервис в остальных районах ухудшается |
| Гибкая комиссия | индивидуальная ставка для ресторанов | часть комиссионной выручки |

# 🎬 КИНОПОТОК — онлайн-кинотеатр

Вы строите стриминговый сервис. Каждый ход — месяц, партия — три года.

Каталог можно арендовать (лицензии — дёшево, сразу, но истекает и есть у конкурентов)
или производить самому (в пятьдесят раз дороже за час, премьера через полгода, зато
навсегда и только у вас). Ни одна из крайностей не работает.

**Среда нестационарна — постоянной оптимальной стратегии здесь не существует.**
Конкурент живой: у него своя касса, каталог и политика, которая отвечает на ваши
решения. Права и талант дорожают вместе с вашим успехом. Совет директоров меняет
цель каждый год, и цель второго года прямо конфликтует со стратегией первого.
Кризисы не рассасываются сами. Замерено: лучшая стратегия, разбитая на три года,
даёт **+85%** к лучшей постоянной настройке рычагов.

### Чем управляет игрок

| Рычаг | Что делает | Обратная сторона |
|---|---|---|
| Цена для новых | основная выручка | база продолжает платить свою — перевод на прайс это отдельное решение |
| Цена с рекламой | приводит тех, кто иначе не заплатит | каннибализация дорогого тарифа |
| Рекламная нагрузка | вторая статья выручки | прямой рост оттока, киноманы уходят первыми |
| Закупка лицензий | каталог сразу | истекает 4.5% в месяц, есть у конкурентов, почти не считается новинкой |
| Слоты студии | сколько проектов идёт параллельно | слот стоит денег, даже когда пустует, и содержание растёт быстрее числа слотов |
| Скидка за год вперёд | касса сразу за 12 месяцев, отток на них не действует | цена зафиксирована и повышения их не касаются |
| Партнёрства и бандлы | оптовый канал: люди приходят тысячами и дёшево | вы получаете долю прайса, они меньше смотрят и уходят разом в конце контракта |
| Маркетинг бренда | ровный фон узнаваемости | работает медленно и при пустом каталоге сгорает впустую |
| Кампания под релиз | кратно усиливает конкретную премьеру | работает только вместе с релизом |
| Пробный период | конверсия в платящих | длинный триал — это подаренные месяцы |
| Качество картинки | меньше раздражения | трафик — крупнейшая переменная статья |
| Технологии и платформа | дешевле час трафика, лучше качество проектов | накопительная инвестиция |
| Data Science | качество алгоритмов | без просмотров бесполезен |
| Раунды инвестиций | деньги на рост | размытие вашей доли |

### Что моделируется

* **Каталог** — два запаса с разной экономикой: арендованный истекает, собственный
  остаётся. Час эксклюзива удерживает как дюжина часов чужой библиотеки.
* **Свежесть** — отдельный запас от глубины. Каталог может не уменьшиться ни на час
  и всё равно терять подписчиков, потому что зритель видит одну и ту же полку.
* **Слейт** — конкретные проекты, а не бюджет. Три решения на каждый: что запустить
  (жанр × масштаб × сегмент), когда выпустить готовое и сколько дать кампании.
  Качество до премьеры видно только вилкой.
* **Запас** — готовый проект не выходит сам. Придержать до зимы выгоднее, чем
  выпустить в июль: сезон входит в шум премьеры в степени 2.2. Но лежать не
  бесплатно — 4.5% шума выветривается за месяц.
* **Переходы по подсказкам** — ключевые слова в советах кликабельны: нажатие
  прокручивает к нужному рычагу, раскрывает свёрнутую группу и подсвечивает блок.
* **Опт против розницы** — партнёрства с оператором, банком, производителем ТВ.
  Люди приходят тысячами и дёшево, но платят долю прайса, смотрят меньше и уходят
  разом в конце контракта. Замерено: «подписывать всё» даёт больше подписчиков
  и меньше денег, чем «подписывать только выгодное».
* **Цена в двух слоях** — прайс для новых и то, что платит действующая база.
  Разрыв копится незаметно и закрывается больно: перевод базы на прайс стоит
  подписчиков. Годовая подписка выключает человека из оттока и из повышений.
* **Четыре сегмента аудитории** — массовый зритель, киноманы, семьи, молодёжь.
  Разная эластичность, терпимость к рекламе, лояльность и объём просмотра.
* **Два тарифа** — зрители сами распределяются между ними; снижение цены дешёвого
  тарифа переманивает людей с дорогого.
* **Часы просмотра как расход** — трафик растёт вместе с лояльностью. Самый лояльный
  зритель — самый дорогой.
* **Похмелье после премьеры** — отдельный запас: чем громче хит, тем больше людей
  отпишется, досмотрев его.
* **Живой конкурент** — рынок один на двоих. У него своя касса, каталог, пайплайн
  и пять читаемых позиций, каждая держится минимум четыре месяца. Он отвечает на вашу
  цену, входит в жанр, где вы сильны, может привлечь раунд — и может обанкротиться.
* **Переток базы** — расти можно, приводя новых или переманивая чужих. Второй способ
  быстрее, но эксклюзив — единственное, чего конкурент не купит теми же деньгами.
* **Дорожающие ресурсы** — права дорожают, когда за них торгуетесь вы оба; талант
  дорожает вместе с вашим успехом. У маховика роста есть тормоз.
* **Цели совета директоров** — своя на каждый год: рост, потом прибыльность, потом
  доля рынка. Провал стоит доли, порезанного бюджета или оценки.
* **Кризисы** — иск, скандал, уход шоураннера, деградация платформы. Каждый месяц
  без решения дороже предыдущего, и само решение тоже дорожает. Приходят тем чаще,
  чем лучше у вас дела.
* **Афиша конкурента** — выводится из его реального пайплайна, известна на месяц
  вперёд, гасится своей премьерой не более чем на 65%.

| Позиция конкурента | Когда | Что делает | Ваш ход |
|---|---|---|---|
| Ровный рост | паритет | цена чуть ниже вашей | стройте каталог |
| Война цен | он проигрывает и богат | демпинг −28%, маркетинг ×1.6 | вниз за ним не идти |
| Давит | он выигрывает | цена +6%, бюджеты ×1.15 | отбирайте зрителя |
| Снимает сливки | касса на исходе | режет контент, поднимает цену | его каталог выдыхается — атакуйте |
| Отступает | деньги кончились | почти не тратит | додавите — рынок ваш |

Своя громкая премьера в месяц чужой частично гасит её (не более чем на 65%):
зритель выбирает, а не уходит совсем.

### Алгоритмы

| Алгоритм | Что делает | Чем платите |
|---|---|---|
| Рекомендательная лента | воспринимаемый каталог больше реального | при слабой модели лента схлопывается в пузырь |
| Прогноз спроса на контент | тот же бюджет закупает нужное | закупка тянется к уже известному, глубина растёт медленнее |
| Персональное удержание | скидка уходит только тем, кто собрался уходить | промахи модели: скидку получают и те, кто остался бы |
| Адаптивная реклама | те же показы при меньшем раздражении | работает только на больших данных |
| Умное сжатие | дешевле час трафика | при слабой модели портится картинка |
| Календарь релизов | премьера растягивается, отток сглаживается | пик подписок ниже |

# 🎟️ БИЛЕТОН — билетный сервис

Вы управляете билетным оператором. Каждый ход — месяц, партия — 36 месяцев,
год начинается в сентябре, с открытия сезона.

Это **двусторонний рынок**: с одной стороны организаторы дают афишу, с другой
зрители покупают билеты. Ни одна сторона не приходит первой сама по себе, и в
этом вся задача. Маркетинг в пустую афишу сгорает целиком; богатая афиша без
зрителей даёт пустые залы, из-за которых организаторы уходят.

**Три решения, вокруг которых собрана игра.**

**Одна выручка, две стороны.** Сервисный сбор платит зритель поверх цены,
комиссию — организатор из своей. Сумма может быть одинаковой, а последствия
разные: сбор виден покупателю на оплате и сравним с ценой у конкурента,
комиссия видна организатору в договоре. Размазать поровну — худший вариант:
субсидировать надо одну сторону, а какую — зависит от каналов.

**Конфликт каналов.** Билетный виджет на сайте организатора — ваша продажа
билетов под его брендом — удерживает его от
ухода и возвращает оборот, который иначе прошёл бы мимо вас. Но продажи через
неё приносят в разы меньше, и эти билеты **не появляются в вашей афише** —
значит, не работают на охват. Поставив виджет всем подряд, вы подрезаете ту самую
аудиторию, ради которой организаторы к вам и приходят. Измерено: оптимум —
клубам и концертам, но не театрам и не спорту.

**Оборот и выручка — разные числа.** Через сервис проходят миллиарды, ваши из
них — проценты. Эквайринг 2.2% вычитается из этих процентов, а не из оборота:
take rate 3% минус эквайринг — почти ноль.

Плюс живой конкурент со своими линиями поведения, цели акционеров на каждый
год, кризисы (перекупщики, упавший на старте продаж сайт, регулятор, отмена
тура) и четыре алгоритма второго порядка — включая тот, что поднимает
конверсию за счёт доверия.

## Алгоритмы: оптимизации второго порядка

Механика общая для всех трёх игр. Ползунок задаёт **число** («цена доставки 149 ₽»).
Алгоритм задаёт **правило** («цена = f(загрузка)»), а правило умеет быть разным
в разных обстоятельствах — поэтому способно улучшить сразу оба конца компромисса,
неразрешимого для одного числа.

Алгоритмы открываются по мере роста качества: `качество = √(данные × команда)`.
Данные копятся только от работы сервиса, команда — от бюджета на Data Science.
Ни то, ни другое по отдельности не работает.

Вкладка «Алгоритмы» показывает **контрфактический разбор**: прошлый ход пересчитывается
заново с выключенным алгоритмом, и видно, сколько он принёс на самом деле. Часто ответ —
ноль: surge бесполезен без перегрузки, персональное удержание — при низком оттоке,
а прогноз — если вы и так угадываете. Так студент видит, что ценность алгоритма —
не свойство алгоритма, а свойство ситуации.

## Структура проекта

```
index.html                      витрина со списком игр
shared/
  rng.js                        детерминированный ГПСЧ (партия воспроизводима по seed)
  i18n.js                       ядро переводов: setStrings() / t() / tx()
  charts.js                     отрисовка графиков на canvas
  format.js                     форматирование чисел и денег
  styles.css                    общая тёмная тема и сетка
  tools/build.js                сборка одиночных файлов игр по манифестам
  tools/serve.js                локальный статический сервер
games/<игра>/
  index.html                    разметка
  build.manifest.js             что и в каком порядке класть в один файл
  src/strings.js                словарь интерфейса { ru, en }
  src/model/config.js           ВСЕ параметры мира: константы, рычаги, алгоритмы
  src/model/engine.js           ядро симуляции — чистые функции, без DOM
  src/model/events.js           случайные события
  src/model/rival.js            живой конкурент: его состояние и политика (кинотеатр)
  src/model/board.js            цели совета директоров (кинотеатр)
  src/model/crises.js           кризисы, которые длятся до решения (кинотеатр)
  src/ui/app.js                 интерфейс: рычаги, графики, отчёты
  tests/*.test.mjs              тесты модели и перевода
  dist/kinopotok-streaming-simulator-v1.10.1.html
                                собранная офлайн-версия (имя — в build.manifest.js)
docs/<игра>/                    разбор формул и сценарии занятий (RU + en/)
```

Вся экономика сосредоточена в `games/<игра>/src/model`. Эти модули не знают про браузер,
поэтому их можно гонять в тестах, в скриптах и строить по ним графики чувствительности.

Общее ядро в `shared/` не знает ни про доставку, ни про кино: словарь в него
**инжектится** вызовом `setStrings()`, а игры отдают только ключи. Сборщик проверяет
коллизии имён между модулями, поэтому дубль на верхнем уровне роняет сборку, а не
приводит к белому экрану.

Текст в моделях хранится парами `{ ru, en }` — оригинал и перевод лежат рядом, и потерять
одну из версий незаметно нельзя. Это проверяется тестами.

## Настройка баланса под свой курс

Все числа вынесены в `games/<игра>/src/model/config.js`: стартовый капитал, эластичности,
отток, стоимость контента, пороги открытия алгоритмов. Менять их можно, не трогая логику.

После правки полезно прогнать `npm test` — свыше 270 проверок для трёх игр. Тесты проверяют
не конкретные числа, а качественные свойства модели (монотонность реакций, внутренние
оптимумы, сходимость P&L, отсутствие NaN, полноту перевода), поэтому переживают
перебалансировку.

## Ограничения моделей

Это учебные модели, а не прогнозные инструменты. В доставке конкурент не реагирует на ваши
действия (в кинотеатре — реагирует), клиенты внутри сегмента однородны, а целые куски реальности (международный рынок, торг
за инвентарь, индивидуальные контракты) свёрнуты в один-два коэффициента. Модели
показывают **структуру** зависимостей, а не предсказывают конкретный рынок.
Подробные списки допущений — в конце каждого `docs/<игра>/economics.md`.
